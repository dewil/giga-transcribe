# local-transcription

Локальная транскрипция записи встречи в markdown - offline и приватно, комплемент к облачным
транскрипт-сервисам. Драйвер над CLI `transcribe-meeting` из этого репозитория (ставится один раз
через `install.sh`).

## Когда применять

- Есть локальный файл записи и нужен транскрипт / заметка встречи, которую не берем из облака.
- Встреча не покрыта тем облачным сервисом, что использует проект.

## Когда НЕ применять

- Встреча есть в облачном сервисе, который дает спикеров с именами - там обычно чище (облако берет
  разметку спикеров из платформы звонка, см. ограничения).
- Нужно только сделать summary готового транскрипта - просто читай md.

## Как

1. Уточни файл(ы). Путь может быть абсолютным или относительным.
2. **Сначала выясни, разложены ли голоса по дорожкам** - пофайлово (экспорт по участникам) или
   каналами внутри файла. Если да, диаризацию не запускай вовсе, спикер известен по построению:
   ```bash
   transcribe-meeting ivan.wav petr.wav --track-names "Иван,Петр"   # дорожка = участник
   transcribe-meeting call.wav --split-channels --track-names "Иван,Петр"
   ```
   Разметка выходит точная и именованная, ручная сверка спикеров не нужна. Дорожки из общего
   микрофона (не изолированные) - протечки чужого голоса отсекаются сами, отключается
   `--no-bleed-filter`.
3. Голоса в одной смешанной дорожке - работает диаризация. Если число участников известно, передай
   `--speakers N`, это заметно надежнее (k=N вместо авто-оценки числа по silhouette).
4. Запусти CLI:
   ```bash
   transcribe-meeting "<файл>" --speakers <N> --title "<тема>" -o "<out.md>"
   ```
   - `--no-diar` - чистый текст без спикеров (быстрее).
   - `-o` - путь вывода (по умолчанию рядом с файлом). Для проектной встречи клади по конвенциям
     встреч проекта.
   - stdout CLI - путь к результату; прогресс идет в stderr.
5. **Длинный файл (>20-30 мин): запускай в фоне** (~10-15 мин на час записи). Можно ускорить
   `--threads N` (распараллеливает матричные операции на многоядерных). Не блокируйся на этом.
6. После получения md:
   - При многодорожечном входе спикеры уже именованные - сверять нечего.
   - При диаризации спикеры **обезличенные**; на длинных репликах разметка надежна (~95%), но
     короткие backchannel ("угу", быстрые вопросы) могут уходить не тому спикеру. Сопоставляй
     `Спикер N -> реальное имя` вручную и проверяй короткие реплики.
   - Summary по этому md выводи сам (смысл и задачи выводятся, а не берутся из движка).

## Ограничения (держать в голове)

- Диаризация: sherpa сегментирует речь, спикеров разводит свой k-means (эмбеддинг сегмента + косинус).
  Длинные реплики размечаются надежно, короткие backchannel - хвост ошибок (в короткий сегмент лезет
  соседний голос). Облачные сервисы дают чистые N спикеров с именами, потому что берут метаданные
  active-speaker из платформы звонка, а не из аудио.

## Зависимости

Нужен CLI `transcribe-meeting`, поставленный через `install.sh` этого репозитория (создает venv с
GigaAM + sherpa-onnx и качает модели диаризации). См. README.
