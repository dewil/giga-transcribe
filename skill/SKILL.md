# local-transcription

Локальная транскрипция записи встречи в markdown - offline и приватно, комплемент к облачным
транскрипт-сервисам. Драйвер над CLI `transcribe-meeting` из этого репозитория (ставится один раз
через `install.sh`).

## Когда применять

- Есть локальный файл записи и нужен транскрипт / заметка встречи, которую не берем из облака.
- Встреча не покрыта тем облачным сервисом, что использует проект.

## Когда НЕ применять

- Встреча есть в облачном сервисе, который дает спикеров с именами - там обычно чище (облако берет
  разметку спикеров из платформы звонка, см. ограничения).
- Нужно только сделать summary готового транскрипта - просто читай md.

## Как

1. Уточни файл(ы). Путь может быть абсолютным или относительным.
2. Если число участников известно - передай `--speakers N`, это заметно улучшает диаризацию. Иначе
   авто, но предупреди, что спикеры будут грубее.
3. Запусти CLI:
   ```bash
   transcribe-meeting "<файл>" --speakers <N> --title "<тема>" -o "<out.md>"
   ```
   - `--no-diar` - чистый текст без спикеров (быстрее).
   - `-o` - путь вывода (по умолчанию рядом с файлом). Для проектной встречи клади по конвенциям
     встреч проекта.
   - stdout CLI - путь к результату; прогресс идет в stderr.
4. **Длинный файл (>20-30 мин): запускай в фоне.** ASR + диаризация однопоточны (~10-15 мин на час
   записи). Не блокируйся на этом.
5. После получения md:
   - Спикеры **обезличенные и приблизительные** (диаризация из микса надежна на ~2-3 голоса; 4+
     нужны пофайловые дорожки). Сопоставляй `Спикер N -> реальное имя` вручную.
   - Summary по этому md выводи сам (смысл и задачи выводятся, а не берутся из движка).

## Ограничения (держать в голове)

- Диаризация из одной смешанной записи упирается в ~2-3 надежных голоса; это не лечится числом
  кластеров / порогом / более сильным эмбеддингом. Облачные сервисы дают чистые N спикеров, потому
  что берут метаданные active-speaker из платформы звонка, а не из аудио.

## Зависимости

Нужен CLI `transcribe-meeting`, поставленный через `install.sh` этого репозитория (создает venv с
GigaAM + sherpa-onnx и качает модели диаризации). См. README.
